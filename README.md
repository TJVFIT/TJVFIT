## Why this is engineering, not vibe coding

- Important guards are mutation-tested: remove the guard, require the test to fail, then restore it.
- Packaged applications are driven directly; this caught duplicate audit writes that a large green unit suite missed.
- Tests that pass against broken code are treated as defects and replaced with discriminating fixtures.
- Untrusted model output is fenced by typed contracts, deterministic engines, least-privilege tools, and explicit approvals.
- Attractive backtest results are rejected when causality, adjusted-price, transaction-cost, or robustness checks fail.

The useful question is not whether AI helped write the code. It is whether the engineer can explain the system, constrain it, run it, break it, repair it, and prove the repair.
